# Submission and demo checklist

Source: official `dataset/01-problem-statement.md`, What to submit.

The video must be at most five minutes, narrated in your own voice: explain how you built the system, then show one real use case running end to end in the UI. It does not require recording all final questions.

## After the accuracy report

1. Review each final scenario against source evidence. Keep timeouts and unsupported conclusions visible; HTTP success is not an accuracy pass.
2. Fix general defects that the evidence demonstrates. Keep the first-run results immutable; reruns belong in a separately named run.
3. Choose one source-verified use case for the video. Manually confirm its visual, citations, resizing and follow-up in the browser. Use a dedicated demo chat; avoid untracked shared corrections.
4. Record roughly 60 seconds of architecture, 2–3 minutes of the actual UI question/evidence/follow-up, then limitations and next steps. The presenter explains decisions in their own words.
5. Finish the 2–3 page write-up: page 1 design, page 2 final results, with a third page only if needed. Include the requested full final answers and visual artifacts; link an appendix/artifact bundle rather than pretending all full responses fit on one page.
6. Confirm an open-source license, public repository, playable video <=5 minutes and accessible write-up/results links. The user submits through OrganizerHQ.
